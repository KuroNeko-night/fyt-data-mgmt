# 仓库维护与目录规范

本文说明源码仓库、开发依赖、运行数据和交付产物之间的边界。业务架构和模块职责以
《项目全景-模块与实现》为准；本文只维护仓库卫生和日常开发约定。

## 根目录保留内容

根目录只保留跨模块配置、Python 兼容入口和项目级文档：

- `README.md`、`AGENTS.md`、`LICENSE`：项目说明、维护约束和许可证。
- `requirements*.txt`、`pyproject.toml`：Python 环境声明。
- `web_server.py`、`web_control_gui.py`：兼容启动与服务控制入口，业务实现不得回流到这里。
- `scripts/*.ps1`：Windows 用户直接执行的安装、启动、停止和密码重置入口；打包器会按需复制到部署包根目录。
- `.editorconfig`、`.gitattributes`、`.gitignore`、`.dockerignore`：编码、换行、忽略和 Docker 构建上下文边界。

内部构建、同步、质量检查和 Windows PowerShell 入口统一放在 `scripts/`；Docker 构建与
Compose 编排放在 `docker/`；部署模板放在 `packaging/`；实现代码按 `core/`、
`web_backend/`、`web-app/`、`tauri-app/` 分层。PowerShell 入口在源码仓统一归类到
`scripts/`，README 与打包脚本按该路径引用；`build_deploy.py` 仍会把用户高频使用的入口
复制到部署包根目录，保证部署后的使用习惯不变。Docker 构建上下文保持为仓库根目录，
因此 `.dockerignore` 必须留在根目录。

## 不进入 Git 的内容

以下内容可以存在于本地，但必须保持未跟踪：

- `.venv/`、`node_modules/`、Rust `target/` 等依赖和编译缓存；
- `web-data/`、`docker-data/`、数据库、备份、日志、PID 和用户上传文件；
- `dist/`、`build/`、前端 `dist/`、Tauri sidecar 和安装包；
- `tmp/`、浏览器验收截图、覆盖率目录、Python 缓存和 IDE 工作区；
- 证书、私钥、Token、管理员密码及其他真实凭据；
- 真实业务表格、报告和包含客户数据的截图。

`secrets/admin-password.example.txt` 只能作为空示例存在。正式凭据通过环境变量、部署系统
或服务器本地受限文件提供，不能为了方便测试写入源码。

## 提交前检查

在仓库根目录执行：

```powershell
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe scripts\check_repository_hygiene.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
npm --prefix web-app run build
npm --prefix tauri-app run build
```

仓库卫生检查扫描 Git 已跟踪文件和未被忽略的新源码，不读取 `web-data` 或被忽略的本地
资料。它会阻止运行数据、生成物、交付压缩包、私钥/Token 特征、非 UTF-8 文本以及已知
中文乱码残留进入仓库。

若要确认忽略规则是否生效，可执行：

```powershell
git status --short --ignored
git check-ignore -v web-data\accounts.sqlite3
```

## 新增文件的归属

- 新业务算法放入 `core/<feature>_core.py`，并在 `tests/` 增加合成数据测试。
- 新 Web 领域能力放入 `web_backend/services/`，HTTP 协议放入 `web_backend/http/`。
- 双端页面分别进入 `web-app/src/`、`tauri-app/src/`，共享视觉值进入 `design-system/`。
- 可复用维护命令进入 `scripts/`，部署目标机脚本和模板进入 `packaging/`。
- 当前实现说明进入 `docs/项目全景-模块与实现.md`；阶段性方案仅在仍有维护价值时保留。
- 新增根文件必须有跨模块或直接用户入口理由，并同步源码包根文件白名单。

## 清理原则

清理前先使用 `git status --short` 区分源码改动和可再生成产物。不得使用会回退用户修改的
`git reset --hard` 或 `git checkout --`。`web-data`、证书、备份和生产配置不能按缓存处理；
删除交付暂存目录前，应先确认最终压缩包与校验文件已经生成并位于预期位置。
