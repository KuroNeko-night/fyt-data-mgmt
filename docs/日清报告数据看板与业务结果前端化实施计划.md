# 日清报告数据看板与业务结果前端化实施计划

> 制定日期：2026-08-05  
> 试点范围：每日到料明细、现场问题；工时对账、采购对账、对账单制作的前端结果展示。

## 一、目标与边界

本次建设包含两条彼此复用的数据链路：

1. 为管理层提供按日查看的日清报告数据看板，首批汇总当日到料与现场问题。
2. 把只适合下载文件查看的业务结果转换为前端可直接阅读的指标、明细和提示，同时保留正式输出报告。

首期管理层权限沿用现有 `admin` 角色，不新增角色或权限表。普通账号仍只能查看自己的任务结果，不能访问跨账号日清数据。后续新增“只读管理者”时，只替换权限判断，不改变日清数据契约。

本轮不实施跨日趋势、问题分类字典、自动定时推送和管理者专用角色；这些能力以本次数据契约为基础继续扩展。

## 二、数据口径

### 2.1 日期

- 业务时区固定为 `Asia/Shanghai`。
- 到料数据按任务的完成时间归入业务日期；同一账号、同一天重复运行的任务均保留并展示，不擅自合并或覆盖。
- 现场问题按问题记录中的 `issue_date` 归入日期，只统计已发布记录。
- 页面、接口和导出报告均明确显示统计日期、生成时间和上述口径，避免把任务完成日误读为实际到货日期。

### 2.2 到料指标

- 任务数：当日成功完成的到料任务数。
- 批次数：所有到料任务结果中的批次数。
- 主料总类数：各批次配置的主料总类数之和。
- 已到货类数：各批次已到货类数之和。
- 未收料类数：各批次未收料类数之和。
- 到料完成率：`已到货类数 / 主料总类数`；分母为 0 时显示 0%，并标记数据不足。
- 未到物料明细：按批次保留物料编码、物料名称、供应商、需求数、已收数和缺口数；缺口数直接取送货计划中的剩余未收数，已收数仅在需求数与缺口数均可计算时生成。

### 2.3 现场问题指标

- 问题数：当天已发布问题数。
- 图片数：问题附带图片总数。
- 主要负责人分布：按 `primary_owner` 计数，直接显示负责人和数量。
- 问题明细：原因、主要负责人、次要负责人、备注、提交人、提交时间和图片。

## 三、共享结果展示协议

新增 Python 纯业务投影模块，将各核心返回结果转换为统一结构：

```text
presentation
├─ kind          结果类型
├─ title         面向用户的标题
├─ summary       一句话结论
├─ metrics[]     标签、数值、说明、语义色
├─ sections[]    标题、列定义、行数据、总行数、截断状态
└─ notices[]     信息、警告或错误提示
```

投影只整理已有业务结果，不重复计算核心算法，不持久化绝对路径，不改变输出文件。Web 端旧任务在读取时即时生成投影；Tauri 长任务响应直接附带同一投影。

首批覆盖：

- 到料明细：批次、未收料类数、已到货类数、主料总类数、完成率，以及逐项未到物料和数量缺口。
- 工时对账：可信度、匹配人数、单方名单、异常人数、异常类型和异常明细。
- 采购对账：双方有效行、成功配对、双方未配对、数量疑点和疑点明细。
- 对账单制作：供应商、月份、输出文件数、总行数和各供应商行数。

## 五、交互与视觉方案

### 5.1 信息阅读路径

1. 首先确认统计日期、更新时间和数据口径。
2. 立即看到到料完成率、未收料类数、现场问题数和涉及负责人数量。
3. 查看各批次到料完成度，数值始终直接显示，不依赖悬停。
4. 点击具体批次，在大号浮窗中核对未到物料、需求数、已收数和缺口数。
5. 查看主要负责人问题分布。
6. 下钻到问题正文与现场图片。

### 5.2 图表选择

- 到料：直接标注的水平完成度轨道，适合少量批次比较和移动端纵向阅读。
- 现场问题：直接标注的负责人水平条形图。
- 核心比例：CSS 圆环只作为辅助编码，旁边始终保留明确百分比和分子/分母。
- 明细：批次主页保持紧凑概览；宽屏浮窗使用全宽表格，窄屏浮窗切换为物料卡片，不缩小文字、不把缺口数藏到横向滚动后。

首期不引入重量级图表依赖。当前数据量和图形类型使用原生 HTML/CSS 更轻、更可访问，也不会增加 Web/Tauri 包体；若后续加入跨日趋势、组合筛选和钻取联动，再评估引入声明式图表库。

### 5.3 响应式与无障碍

- 1440px：到料与现场问题并列，主证据区域优先。
- 920px：单列内容，指标保持两列。
- 390px/360px：首屏先展示日期和核心指标，图表使用纵向条目；批次详情浮窗接近全屏，未到物料改为卡片，图片横向滚动但隐藏滚动条。
- 关键值、数据口径和错误提示不依赖颜色或悬停。
- 交互控件满足至少 44px 触摸目标。
- `prefers-reduced-motion` 下关闭进度轨道入场和数值过渡。
- 刷新失败时保留上次成功数据并显示“数据可能已过期”。

## 六、验收门槛

### 6.1 功能

- 管理员可以查看指定日期全量日清数据并导出 Excel。
- 普通账号访问日清接口和页面入口均被拒绝或不渲染。
- 到料与现场问题按既定业务日期正确归桶。
- 旧任务无需重跑即可展示业务结果。
- 新到料任务可直接查看具体未到物料和缺口数量；只有旧汇总的历史任务明确提示重新处理后补全明细。
- 工时对账、采购对账、对账单制作和到料结果在前端可直接阅读，输出报告仍可下载。
- 所有返回值不含服务端绝对路径、密码、令牌或其他敏感信息。

### 6.2 数据与性能

- 大型异常列表只返回有限前端明细并显示真实总数。
- 日清查询使用日期和状态索引，不扫描无关历史文件。
- 页面不引入持续动画或高频重绘。
- 刷新请求不会清空上一次成功结果。

### 6.3 视觉与交互

- 1440、1024、920、640、390、360px 无横向溢出。
- 亮色、暗色、键盘焦点、触摸目标和减少动画状态通过检查。
- 到料完成度、负责人分布和问题明细在没有悬停的截图中仍可读。
- 批次详情浮窗在桌面端不需要横向滚动即可看到全部数量列，360px 下同一卡片内直接显示需求数、已收数和缺口数。
- 无调试文本、内部动作名、原始 JSON 或绝对路径出现在客户界面。
