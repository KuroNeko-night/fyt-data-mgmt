# 峰运通数据管理系统前端风格化改造与美术资源制作计划

> 制定日期：2026-08-03  
> 适用范围：`web-app/`、`tauri-app/`、共用 `assets/` 与离线美术资源生成脚本  
> 前置文档：[前端视觉统一与工作台美化实施计划.md](./前端视觉统一与工作台美化实施计划.md)  
> 本文只负责风格、动效和美术资源设计，不直接实施业务代码。

## 一、这次改造要解决什么

迁移后的前端已经完成了结构统一，但目前出现了新的问题：

- 视觉过于素净，页面之间缺少记忆点；
- 侧栏、顶栏、工作区虽然统一了颜色，却没有形成鲜明的品牌空间；
- 页面切换和任务状态变化的反馈不足，操作感觉偏“静态表单”；
- 空状态、上传状态、执行状态和完成状态缺少连续的视觉叙事；
- 现有插画资源比较零散，无法支撑 Web 与 Tauri 的统一气质；
- 如果继续无规则地添加渐变、阴影和动画，很容易重新退化成装饰堆叠。

本计划的目标不是把每个页面都塞进一张插画，而是建立一套有辨识度的视觉语言：

> **夜航蓝图 + 数据纸面 + 流动信号**

它应该让用户感到：这是一个正在处理真实业务数据的专业工作台，而不是一个静态的后台模板。

## 二、视觉方向：夜航蓝图 · 数据纸面 · 流动信号

### 2.1 夜航蓝图：应用外壳

应用外壳继续使用深海军蓝，但增加非常克制的“蓝图”特征：

- 侧栏背景保留深海蓝渐变；
- 叠加极低透明度的坐标网格、等高线和少量节点；
- 网格只作为背景层，不作为内容层，不影响文字对比度；
- 当前导航项使用一条有方向感的蓝青信号轨；
- 侧栏收起时保留信号轨和图标，不让导航变成无状态的黑色栏；
- 顶栏使用半透明冷白表面，但取消厚重玻璃和大范围模糊。

蓝图元素只能承担两件事：

1. 建立品牌空间；
2. 指示当前所在模块或正在运行的状态。

不能把网格、节点、数字和伪系统标签当成装饰噪声。

### 2.2 数据纸面：内容工作区

内容区不再是“很多白卡片平铺”，而是模拟一张有层次的业务纸面：

- 页面画布使用冷灰蓝，不使用暖米色；
- 主要工作区使用白色或深色表面；
- 区块之间通过留白、边线和内容密度区分，不给每一块都加厚边框；
- 表格、任务流水、复核区保持高密度，重点信息通过左侧状态轨、数字和行内动作强调；
- 大型模块只保留一层主要容器，避免“卡片套卡片”；
- 重要结果出现时使用一条“结果纸带”从任务区延伸到下载区，形成完成感。

### 2.3 流动信号：交互和动效

把“数据从输入到输出”的过程变成全项目统一的动效隐喻：

- 上传：文件节点进入工作区；
- 排队：节点停留在等待轨道；
- 处理中：信号沿路径移动；
- 待复核：信号停在一个带呼吸边缘的检查节点；
- 已完成：路径闭合，结果文件向下展开；
- 失败：路径断开并显示客户化错误提示，不使用剧烈震动。

动效应该让用户理解状态，不应该让页面持续“自我表演”。

## 三、改造后的签名元素

整个项目只选择 5 个签名元素，所有页面都从这 5 个元素中取用，避免每页另造一套风格。

### 元素 A：信号轨 `Signal Rail`

视觉：一条 2px 的蓝青渐变线，旁边有 6～8px 的状态节点。

使用位置：

- Web/Tauri 侧栏当前项；
- 任务行左侧状态轨；
- 复核步骤的当前步骤；
- 上传/执行/结果的工作流连接线。

规则：

- 静态时只显示线和节点；
- 处理中才允许有一个短距离移动的光点；
- 失败状态改为断线和红色短段，不使用闪烁；
- 所有状态必须同时显示文字，不能只显示颜色。

### 元素 B：数据丝带 `Data Ribbon`

视觉：由 2～3 条细线构成的抽象数据流，线条有轻微弧度，节点像文件、表格和结果之间的连接点。

使用位置：

- Web 工作台状态区右侧；
- Tauri 首页欢迎区；
- 登录页品牌插画的背景层；
- 服务器模式选择页的连接说明区域。

规则：

- 只使用一张主插画，不为每个业务模块生成一张相似插画；
- 插画本身不包含界面、按钮、中文文字或假数据；
- 放在标题和操作区的右侧，禁止覆盖文字和控件；
- 移动端默认隐藏完整插画，仅保留一条 CSS/SVG 信号线。

### 元素 C：纸带分隔 `Paper Fold`

视觉：极细的折线、切角或纸张边缘，用来表达“任务记录”和“输出结果”之间的层次。

使用位置：

- 任务流水中任务与输出文件的连接；
- 人工复核结果区；
- 报表生成完成区；
- 数据库文件详情抽屉。

规则：

- 优先使用 CSS 边线和伪元素实现，不用生成图片；
- 每个页面最多出现 1～2 次；
- 不使用拟物纸张阴影，不做真实纸张纹理堆叠。

### 元素 D：坐标网格 `Blueprint Grid`

视觉：非常淡的 32px 或 40px 网格，配合局部等高线。

使用位置：

- 深色侧栏背景；
- 工作台深色状态带；
- 登录页左侧品牌区；
- Tauri 模式选择页。

规则：

- 使用 CSS `linear-gradient` 或轻量 SVG，不调用图片模型生成；
- 透明度控制在 0.04～0.09；
- 网格不在白色表格和长文本区域使用；
- 减少动画时完全静止。

### 元素 E：状态印章 `State Stamp`

视觉：小型状态文字、节点和时间组合，不是装饰性胶囊。

使用位置：

- 任务状态、复核状态、文件权限、账号状态；
- 工作台最近更新时间；
- Tauri 任务面板的进度阶段。

规则：

- 文字必须是客户语言；
- “实时”只有在真的有自动刷新时使用；
- 颜色只做辅助，必须有状态文字；
- 不能在一个区块中同时出现 5 种彩色印章。

## 四、颜色、材质与排版延续规则

本次风格化不推翻前一份统一设计计划，而是在其上增加视觉层。

### 4.1 颜色

基础令牌继续使用：

- 深海军蓝：`#0F1C33`；
- 品牌蓝：`#2F6BFF`；
- 品牌青：`#21C8C6`；
- 页面冷灰：`#F4F7FB`；
- 成功：深绿；
- 待处理：琥珀；
- 失败：红色。

新增的风格颜色只允许作为视觉层令牌：

- `--fyt-glow-blue: rgba(47,107,255,.18)`；
- `--fyt-glow-cyan: rgba(33,200,198,.14)`；
- `--fyt-grid-light: rgba(255,255,255,.06)`；
- `--fyt-grid-dark: rgba(15,28,51,.06)`；
- `--fyt-signal-gradient: linear-gradient(90deg,#2F6BFF,#21C8C6)`。

不要在每个页面单独定义 `--hero-blue`、`--board-cyan`、`--admin-purple` 等变量。

### 4.2 材质

允许使用：

- 细边框；
- 轻微内阴影；
- 低透明度网格；
- 纸带切角；
- 局部蓝青光晕；
- 轻微噪点纹理。

不允许使用：

- 大面积玻璃模糊；
- 霓虹发光文字；
- 过度 3D 透视卡片；
- 仿金属、仿木、仿纸张真实纹理；
- 生成图上的伪按钮、伪表格和不可读中文。

### 4.3 排版

- 正文继续使用微软雅黑/苹方系统字体；
- 数字、时间、批次号使用等宽数字；
- 大标题 24～32px，区块标题 18px，正文 14px；
- 重要状态数字可以使用 28～40px，但必须有文字口径；
- 生成图片不承担 UI 文案，所有标题、按钮和表格文字都由 React/HTML 渲染。

## 六、每个美术资源的设计与使用方法

### A01：登录页数据丝带

**文件**：`auth-data-ribbon.webp`

**目的**：让登录页保留品牌记忆点，同时把“数据进入正确工作流”的概念表达出来。

**画面要求**：

- 深海蓝背景；
- 蓝青色的抽象数据丝带、节点、纸张和表格轮廓；
- 右下或右侧留出大块负空间，避免压到登录品牌文案；
- 不出现人物、电脑屏幕、按钮、真实表格、品牌文字或水印；
- 气质专业、安静、有少量未来感，不做科幻城市和霓虹赛博朋克。

**使用方法**：

- Web `AuthScreen` 左侧作为整块背景图；
- `background-position: right center`，桌面端完整显示；
- 980px 以下隐藏图片，只保留 CSS 网格和一个小型品牌标记；
- 不在图片上加彩色遮罩，必要时只在边缘做与背景同色的渐隐；
- `alt=""`，因为图片为装饰，主标题由 HTML 提供。

**动效**：

- 首次进入时整体淡入 420ms；
- 只允许一条 CSS 伪元素信号线移动 1 次；
- 不让整张图片持续漂移。

**生成提示词**：

```text
用途：品牌登录页背景插画
类型：宽幅抽象业务数据流插画
主体：深海蓝空间中的蓝色与青色数据丝带、文件节点、表格轮廓和有秩序的连接路径
构图：宽幅横向，右侧视觉重点，左侧和中间保留大面积深色负空间用于放置中文品牌文案
风格：高级企业软件品牌插画，克制、精确、轻微未来感，矢量感与柔和 3D 纸张质感结合
配色：#0F1C33、#16294A、#2F6BFF、#21C8C6，低饱和，不使用紫色和荧光粉
要求：不出现人物、真实产品界面、按钮、可读文字、数字、水印、Logo、霓虹城市、赛博朋克元素
```

### A02：工作台数据丝带

**文件**：`workbench-data-ribbon.png`

**目的**：为工作台提供一个可复用的主视觉锚点，使状态板不再只是文字和数字。

**画面要求**：

- 透明背景抠图后保留 3～5 个抽象文件节点；
- 一条数据丝带从左下向右上延展；
- 节点可分别暗示输入、处理、复核和输出，但不能画成具体软件界面；
- 线条边缘清晰，适合叠放在深色和浅色表面上；
- 不要投射大面积阴影，不要使用绿色抠图色作为主体颜色。

**使用方法**：

- Web `DispatchBoard` 右上角，宽度约 280～360px；
- Tauri `HomePage` 欢迎区可复用，但裁剪范围和透明度单独适配；
- 移动端不加载完整图片，改为 `Signal Rail` SVG；
- `loading="eager"` 只用于工作台首屏，其他页面使用 `lazy`；
- `aria-hidden="true"`。

**动效**：

- 图片本身静止；
- 使用 CSS/SVG 在图片上方叠加一颗 900ms 的信号点，仅在任务刷新或执行中出现；
- 不用 CSS 直接对 PNG 做旋转和缩放。

**生成提示词**：

```text
用途：数据管理工作台首屏装饰插画
类型：透明背景抽象业务数据流插画，先使用完全平整的 #00FF00 背景，便于后续抠图
主体：三到五个抽象文件节点、表格纸片、数据丝带、圆形检查节点和输出文件节点
构图：横向，主体集中在画面中下部，四周留透明安全边距，适合放在 UI 卡片右上角
风格：精致的企业数据产品插画，纸张、玻璃和细线结合，结构清晰，低饱和
配色：深海蓝、品牌蓝、品牌青、少量白色，不使用紫色、荧光绿和红色
要求：背景必须是完全均匀的 #00FF00；不出现文字、按钮、真实软件界面、Logo、水印、人物和复杂阴影
```

抠图流程：生成后用本地抠图脚本去除 `#00FF00`，检查透明角落、边缘溢色和主体覆盖率，再导出 PNG/WebP。

### A03：本地/服务器模式连接桥

**文件**：`remote-bridge.png`

**目的**：让 Tauri 的本地模式和服务器模式选择页有清晰的连接隐喻，减少纯文字卡片的单调感。

**画面要求**：

- 一侧是本地文件节点，一侧是远程工作台节点，中间由一条蓝青连接桥连接；
- 不画真实网络设备、云服务 Logo 或公网地址；
- 画面适合正方形裁剪；
- 两种模式都可复用，不暗示某个模式一定更优。

**使用方法**：

- Tauri `ModePicker` 两个模式卡片共用同一图，分别使用不同 `object-position` 或裁剪；
- 服务器模式选中时提高蓝青路径亮度；
- 本地模式选中时提高文件节点亮度；
- Web 不使用该资源，避免把桌面模式概念带入账号工作台。

**动效**：

- 选中模式变化时使用 240ms 的节点亮度与边框过渡；
- 不让桥梁在未选中时持续流动。

**生成提示词**：

```text
用途：桌面端本地模式与服务器模式选择页插画
类型：透明背景正方形抽象连接插画，使用完全均匀的 #00FF00 背景抠图
主体：左侧本地文件夹与表格节点，右侧远程工作台节点，中间是一座由蓝青数据线组成的连接桥
构图：居中、正方形、边缘留安全距离，适合卡片右侧或顶部
风格：专业企业软件、精确、轻量 3D 纸片和细线结构，不能像网络安全宣传海报
配色：#0F1C33、#2F6BFF、#21C8C6、白色，少量暖灰
要求：无文字、无云厂商 Logo、无 IP 地址、无按钮、无水印、无人物；背景完全均匀 #00FF00
```

### A04：任务中心空状态

**文件**：`empty-task-archive.png`

**目的**：新账号或刚安装系统时，解释“任务还没有开始”，同时引导用户回到业务模块。

**画面要求**：

- 一叠整齐的任务纸张、一个小型信号节点和未开启的轨道；
- 不画悲伤人物，不使用“空空如也”的夸张情绪；
- 透明背景，适合浅色和深色表面；
- 不出现文字。

**使用方法**：

- Web `TaskCenterPage` 和 Tauri 任务中心共享；
- 图片宽度 180～220px，移动端 140～160px；
- 图片下方由页面提供客户化文案和“开始新的业务处理”按钮；
- 不把图片作为按钮，按钮仍由 HTML 渲染。

**生成提示词**：

```text
用途：企业数据管理系统任务中心空状态
类型：透明背景方形轻量插画，使用完全均匀的 #00FF00 背景抠图
主体：一叠整齐的任务纸张、一个安静的蓝青状态节点、一条尚未启动的短数据轨道
风格：克制、专业、友好、轻量纸片与细线结合，不可爱卡通，不悲伤
构图：居中，主体紧凑，四周透明留白
配色：深海蓝、蓝色、青色、白色、浅灰
要求：无文字、无按钮、无数字、无 Logo、无水印；背景完全均匀 #00FF00
```

### A05：数据库空状态

**文件**：`empty-library-shelf.png`

**目的**：表达“数据库还没有可见文件”或当前筛选没有结果。

**画面要求**：

- 轻量档案架、文件夹和一个空出的文件位置；
- 文件夹不写文字，不出现真实公司名称；
- 不能画成办公室场景或真实书架照片；
- 颜色比任务空态更偏青灰，保持安静。

**使用方法**：

- Web `FileLibraryPage` 空态；
- 过滤无结果时缩小图片并配“换一个筛选条件”操作；
- 首次数据库为空时配“上传第一份文件”主按钮；
- 管理员回收站为空时可以复用，但文案必须不同。

### A06：车间每日问题空状态

**文件**：`empty-workshop-note.png`

**目的**：在移动端车间问题页面当天没有记录时，表达“可以开始上报”，而不是“系统没有数据”。

**画面要求**：

- 手机拍摄框、现场记录卡片、一个小型提示节点；
- 不出现真实工厂品牌、人物脸部和具体设备型号；
- 画面纵向安全区充足，适合手机页面；
- 不生成图片中的中文说明。

**使用方法**：

- Web `WorkshopIssuePage` 的当天空态；
- 纵向页面宽度 160～220px；
- 上传区仍必须是可点击的原生控件区域，插画不能覆盖输入控件；
- 发布成功后切换为实际问题列表，不重复显示空态。

### A07：人工复核空状态

**文件**：`empty-review-check.png`

**目的**：表达“当前没有待人工确认的事项”，让复核页面在空状态时仍有明确结束感。

**画面要求**：

- 一张带检查标记的业务纸张、一个闭合信号节点；
- 不使用夸张的大勾、不画奖杯、不暗示绩效；
- 颜色以成功绿和蓝色为主，透明背景。

**使用方法**：

- `ReviewPanel` 和任务中心筛选为“待复核”但无结果时使用；
- 仅在没有待处理数据时显示；
- 失败或服务端异常必须使用错误组件，不能误用该图。

### A08：管理员网络图

**文件**：`admin-network-map.png`

**目的**：给系统管理和审计页面一个更有层次的首屏，不把复杂后台做成普通卡片墙。

**画面要求**：

- 抽象用户节点、权限边界、消息和数据文件节点；
- 不显示真实账号、权限名称、数据库表名和内部路径；
- 适合横向标题区，主体靠右，左侧留标题空间；
- 使用深海蓝、蓝色和少量琥珀色，琥珀仅表示待处理。

**使用方法**：

- 只给管理员 `AdminPage` 首屏或审计标签页使用；
- 普通成员不加载该资源；
- 右侧宽度 240～320px，避免挤压账号表格；
- 移动端隐藏，改用小型状态轨。

### A09：成功结果纸带

**文件**：`success-result-fold.png`

**目的**：给“已生成结果”提供轻量完成感。

**使用方法**：

- 仅用于结果区第一次出现时；
- 图片宽度 96～128px，旁边显示真实文件列表和下载按钮；
- 不用作成功通知的唯一表达；
- 同一页面刷新时不要重复播放。

### A10：失败恢复路径

**文件**：`failure-recovery-path.png`

**目的**：把失败表达成“有下一步可做”，而不是把用户吓退。

**使用方法**：

- 失败任务详情、结果区和任务中心错误空态；
- 图片只在存在可恢复动作时显示，例如重新处理、补充文件、查看复核；
- 不在网络断开、权限拒绝等不可恢复错误上使用，改用文字通知；
- 失败图使用暗红、琥珀和蓝色，但不做闪烁。

## 七、OpenAI 对话生图的统一规范

美术资源由实施模型在当前 Codex/ChatGPT 对话中调用 OpenAI 内置图像生成工具完成。`jojo` 只是当前会话可能经过的外部中转站名称，不是项目中的模型类型、服务端组件或运行环境；不得把它写入仓库配置、前端代码、构建流程或应用运行时。

普通资源生成默认使用对话内置工具，不需要在项目中配置 `OPENAI_API_KEY`，也不创建本地网络请求脚本。A01～A10 是不同资产，必须逐项生成；同一资源需要多个方案时，也应逐次生成和比较，不能把不同资源混在一次变体请求中。

提示词使用 OpenAI 推荐的结构化格式。标签保持稳定，具体内容可以使用中文：

```text
Use case: <stylized-concept / illustration-story / ui-mockup>
Asset type: <资源将用于哪个页面、区域和状态>
Primary request: <本次要生成的核心视觉>
Input images: <Image 1: reference image / edit target / supporting input>（没有则省略）
Scene/backdrop: <环境、背景或纯色色键要求>
Subject: <主体及业务隐喻，不描述可交互 UI 文案>
Style/medium: <专业企业软件插画、克制、精确、轻量纸片和细线>
Composition/framing: <横向或方形、主体位置、安全留白和裁切要求>
Lighting/mood: <柔和、可信、安静，不使用戏剧化强光>
Color palette: <品牌蓝、青绿及受控的状态色，不擅自引入新主色>
Materials/textures: <纸张、细线、节点、低对比网格等材质>
Text (verbatim): none
Constraints: <必须保留的构图、尺寸、边距、主题和无障碍约束>
Avoid: <中文 UI、假数据、Logo、水印、按钮、表格文字和完整网页截图>
```

资源分类原则：

- A01～A03 等抽象主视觉优先使用 `stylized-concept`；
- A04～A10 等带有轻量业务叙事的空状态优先使用 `illustration-story`；
- 只有需要表达布局方向的非最终界面示意图才使用 `ui-mockup`，且不能把生成的界面截图当作产品 UI。

### 7.1 对话内生成与验收流程

1. 先确定资源编号、用途、提示词版本、尺寸、主题策略和禁用项；
2. 在当前对话中为该资源单独调用一次内置图像生成工具；
3. 如使用参考图或编辑已有图片，明确标注每张输入图的角色；编辑任务必须列出“只改什么、保持什么不变”；
4. 生成后检查主体、风格、构图、文字准确性、强制约束和禁用项；
5. 不合格时只提出一个有针对性的调整，再次生成并重新检查，避免一次加入多项互相冲突的修改；
6. 预览稿可以保留在对话默认生成位置；项目正式使用的选定图片必须复制进工作区，不能只引用 `$CODEX_HOME/generated_images/` 下的文件；
7. 不覆盖已有资产，重新生成使用 `-v2`、`-v3` 等版本文件名，验收后再更新资源清单指向。
8. 每批资源完成后记录最终保存路径、最终提示词、采用的生成方式和验收结果，方便后续模型继续迭代。

### 7.2 生成时的禁止内容

- 不让模型生成中文 UI 文案；
- 不让模型生成 Logo 或品牌字样；
- 不让模型生成真实账号、文件名、IP 地址和业务数据；
- 不让模型生成完整网页截图作为最终 UI；
- 不让模型生成导航图标、箭头和简单状态图标；
- 不用同一张图裁成 10 个业务模块的缩略图；
- 不把生成图当作可交互组件；
- 不把 OpenAI CLI/API 的 `model`、`quality`、`background`、输出路径等参数当作对话内置工具参数。

### 7.3 透明背景资源流程

对话内置工具默认不提供原生透明背景参数。透明资源先生成纯色色键背景，再使用 OpenAI `imagegen` 技能自带工具做本地抠图：

1. 默认要求模型使用完全均匀的 `#00FF00` 背景；主体包含绿色时改用 `#FF00FF`；
2. 提示词必须明确背景无阴影、无渐变、无纹理、无反射、无地面、无接触阴影，主体四周保留充足安全边距，且主体不得使用色键颜色；
3. 检查生成结果后，把选中的原始图从对话默认生成位置复制到工作区或临时处理目录；
4. 调用当前 Codex 环境安装的 `$CODEX_HOME/skills/.system/imagegen/scripts/remove_chroma_key.py`，不得在项目中复制或重写该工具；
5. 默认使用 `--auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill`；如仅有轻微边缘溢色，可再尝试 `--edge-contract 1`；
6. 验证输出具有 alpha 通道、四角透明、主体覆盖合理、边缘无明显色键残留且未被裁切；
7. 最终 PNG/WebP 必须落入项目 `assets/generated/`，原始大图和未采用变体不得进入发布包。

复杂毛发、烟雾、玻璃、液体、羽毛、反光物体和半透明材质不适合简单色键抠图。本计划的资源继续使用纸张、线条和不透明节点；若未来确实需要原生透明，应先征得用户确认，再考虑使用需要本地密钥的 CLI `gpt-image-1.5` 路径。不得静默切换模型或执行方式。

## 八、对话内图像生成的执行边界

### 8.1 默认执行路径

- 实施模型在当前对话中调用 OpenAI 内置图像生成工具；
- 对话内置工具负责实际的 GPT Image 模型选择；不得在项目配置中强制指定 `gpt-image-2`，也不得为内置工具臆造本地接口参数；
- 多个不同资源逐项调用，生成后逐项检查和选择；
- 内置工具不可用或生成失败时，应先向用户说明，再由用户决定是否启用需要本地 `OPENAI_API_KEY` 的 OpenAI CLI 备用路径；
- 不创建一次性 SDK 调用器，也不让 Web、Tauri、Python 服务端或浏览器在运行时发起生图请求。

### 8.2 仓库与安全边界

- 仓库只保存提示词、资源清单、最终选定图片和必要的本地后处理/同步工具；
- 提示词文件和 manifest 只记录制作规范、版本、尺寸、用途、最终文件与验收状态，不负责调用模型；
- 外部中转站的名称、地址、认证信息和用户曾在对话中提供的密钥不得写入仓库、日志、截图、测试、发布包或项目文档；
- 不要求实施者设置任何中转站专用环境变量；普通对话生图也不要求设置 `OPENAI_API_KEY`；
- 选中的项目资产必须从对话默认生成目录复制到工作区，再进行抠图、压缩、同步和引用；
- 原始生成缓存、失败变体和中间处理文件不参与 Web/Tauri 构建，也不进入发布包。

### 8.3 资源版本管理

每个资源维护：

```json
{
  "id": "workbench-data-ribbon",
  "version": "v1",
  "generation_mode": "openai-conversation-image-generation",
  "prompt_file": "art-prompts/workbench-data-ribbon.md",
  "source_size": "1536x1024",
  "final_files": ["workbench-data-ribbon.png", "workbench-data-ribbon.webp"],
  "background": "chroma-key-removed",
  "usage": ["web-workbench", "tauri-home"],
  "alt": "装饰性数据流插画"
}
```

不能覆盖旧资源。重新生成使用 `-v2`、`-v3`，通过视觉验收后再切换 manifest 指向。

- `tauri-app/public/illustrations/generated/` 或对应资源目录。

加载规则：

- 首屏主视觉使用 `loading="eager"`、`decoding="async"`；
- 首屏以下空状态使用 `loading="lazy"`；
- 大图通过 `srcset` 提供 1x/2x；
- 背景图优先使用 CSS `background-image`，内容插画使用 `<img>`；

性能预算建议：

- 登录主视觉：压缩后不超过 350KB；
- 工作台主插画：不超过 220KB；
- 单个空状态：不超过 120KB；
- 透明 PNG 只保留必要尺寸，WebP 用于实际加载；
- 原始生成图不进入发布包。

## 十、页面风格化改造顺序

### 阶段 0：风格锁定

输出：

- 一页风格板：颜色、材质、字体、网格、信号轨、数据丝带、纸带分隔；
- Web 工作台桌面版和移动版概念图；
- Tauri 首页和模式选择概念图；
- 资源清单和提示词版本。

验收：

- 视觉方向只有一套，不同时保留“工业深灰”“玻璃 SaaS”“霓虹科技”三套气质；
- 主要页面的第一视口、信息层级和品牌锚点明确；
- 没有把生成图误当作可交互 UI。

### 阶段 1：美术资源制作

顺序：

1. A01 登录页主视觉；
2. A02 工作台数据丝带；
3. A03 Tauri 模式连接桥；
4. A04～A07 四个常用空状态；
5. A08 管理员网络图；
6. A09/A10 成功和失败状态资源，按实际页面需要生成。

每完成一张图，先做单图检查，再接入页面；不能批量生成后把所有问题留到最后。

### 阶段 2：应用外壳动效

先改 Web/Tauri 侧栏、顶栏、路由过渡、抽屉、主题切换和减少动画。

验收重点：

- 页面切换有连续性但不拖慢操作；
- 当前导航信号轨与页面标题切换同步；
- 移动端更多抽屉有清晰进出场和焦点管理；
- Tauri 快捷面板在窄窗口改为覆盖式抽屉。

### 阶段 3：工作台风格化

重点改造：

- 当前状态区增加数据丝带和动态信号轨；
- “需要处理”改为可行动的视觉焦点；
- 最近任务用纸带分隔任务与输出；
- 趋势图使用轻量 SVG/CSS，数字直接显示；
- 空状态、刷新、错误和成功都形成一致的状态叙事。

不要让主视觉占据超过首屏 25% 的垂直空间，不要让图占据任务内容的注意力中心。

### 阶段 4：高频业务流程

按以下顺序推广：

1. `FeatureWorkspace` 上传与执行；
2. `ReviewPanel` 人工复核；
3. `TaskCenterPage` 任务列表和结果文件；
4. `FileLibraryPage` 数据库；
5. `WorkshopIssuePage` 移动端每日问题；
6. 报表、批次、消息、安全；
7. 管理员和主数据页面。

每个页面至少接入一个签名元素，但不强制每个页面都放一张生成插画。

### 阶段 5：Tauri 风格化

- 首页接入 A02 的桌面裁剪版或专用变体；
- 模式选择接入 A03；
- 任务中心复用 A04；
- 业务页统一 `FeatureUi` 的任务轨、步骤线和结果纸带；
- 设置、关于、工具页只使用令牌、状态轨和空态，不再新增插画。

### 阶段 6：清理和视觉回归

- 删除旧的装饰动画、重复渐变、废弃空状态资源和无引用图片；
- 删除只用于旧工作台的 CSS 覆盖层；
- 在所有页面验证图片加载、暗色、移动端和减少动画；
- 更新 `docs/项目全景-模块与实现.md`，记录实际使用的资源和动效。

## 十一、动效规格

### 11.1 动效令牌

```css
--fyt-motion-fast: 120ms;
--fyt-motion-base: 180ms;
--fyt-motion-panel: 260ms;
--fyt-motion-page: 360ms;
--fyt-motion-signal: 900ms;
--fyt-ease-standard: cubic-bezier(.2,.75,.25,1);
--fyt-ease-spring: cubic-bezier(.22,1.2,.36,1);
```

### 11.2 页面进入

- 顶栏标题淡入并轻微上移 4px，240ms；
- 首个主要区块 300ms；
- 后续区块按 40ms stagger，最多延迟 120ms；
- 刷新数据不重播页面入场，仅更新局部组件。

### 11.3 导航

- 当前项信号轨从 0.55 缩放到 1，180ms；
- 图标只允许 2px 的位置反馈，不做持续旋转；
- 移动端更多抽屉从底部上移 12px + 淡入，260ms；
- 抽屉关闭后焦点回到触发按钮。

### 11.4 上传与任务

- 文件拖入：边框变为青色，背景轻微明暗变化，900ms 呼吸；
- 上传成功：文件行从下方进入 180ms，显示一个短暂成功节点；
- 处理中：仅状态节点有 1.6s 低频呼吸，不让整行闪烁；
- 进度：只动画 `width` 或 SVG `stroke-dashoffset`；
- 待复核：复核节点出现一次 240ms 聚焦环；
- 完成：结果纸带展开 320ms，下载按钮随后出现；
- 失败：错误区短暂偏移 2px 或边框变色，不使用剧烈抖动。

### 11.5 页面切换和主题

- 支持 View Transition 时使用页面级淡入淡出；
- 不支持时使用 CSS fallback；
- 主题切换只过渡背景、边框和文字颜色 180ms；
- 不把所有子元素同时放大或重排。

### 11.6 减少动画

`prefers-reduced-motion: reduce` 或 Tauri 设置开启后：

- 删除所有循环动画、路径流动、漂浮和 stagger；
- 页面切换只保留即时显示或极短透明度变化；
- 进度和状态仍以颜色、文字和数值更新；
- 抽屉仍需有明确显示/隐藏状态，但不使用位移动画。

## 十二、可访问性和客户体验

- 生成图不能替代按钮、标题、状态文字和表格数据；
- 装饰资源统一 `aria-hidden="true"`；
- 空状态插画下面必须有客户化说明和下一步操作；
- 状态颜色必须有文字和图形冗余；
- 所有动效不能阻碍点击、输入和键盘操作；
- 图片加载失败时显示 CSS/SVG fallback；
- `alt` 文案描述业务意义，不描述“图片里有一张图”；
- 不把“AI 生成”“模型”“提示词”等开发过程展示给客户。

## 十三、视觉资源验收清单

### 单图验收

- 主体没有被裁切；
- 没有中文乱码、假按钮、假表格、假 Logo 和水印；
- 颜色符合品牌令牌；
- 透明资源四角透明；
- 边缘没有明显绿色抠图溢色；
- 2x 尺寸下线条仍然清晰；
- 浅色和深色表面都能使用，或明确只用于某一主题；
- 不携带真实业务数据。

### 页面验收

- 图片不会覆盖标题、表格、输入框和主要按钮；
- 图片加载失败时布局仍完整；
- 首屏主视觉占比适中，不压过任务内容；
- 移动端没有大面积空白和横向溢出；
- 空状态图不在有真实数据时闪现；
- 页面滚动、抽屉、弹窗和任务刷新没有动画叠加卡顿。

### 双端验收

- Web 与 Tauri 使用同一资产 manifest；
- 图片路径经过发布包测试，不依赖开发机绝对路径；
- Tauri 本地和远程模式都能加载必要资源；
- Web 局域网静态部署不需要访问外部图片 CDN；
- 发布包不包含原始生成缓存和 API key。

## 十六、完成定义

只有满足以下条件，风格化改造才算完成：

- 项目拥有一套可解释的签名视觉语言，而不是随机新增的渐变和插画；
- 每张美术资源都有尺寸、提示词、页面位置、主题策略和 fallback；
- 美术模型只在离线资源制作阶段使用，运行时不暴露 key；
- Web 与 Tauri 的外壳、状态轨、任务轨和动效语言一致；
- 工作台首屏更有记忆点，但关键数据和操作仍然优先；
- 动画表达状态变化，不造成视觉疲劳或性能问题；
- 移动端、暗色、减少动画和空状态都经过验证；
- 发布包不包含 API key、原始生成缓存、调试文案和不可用图片。
