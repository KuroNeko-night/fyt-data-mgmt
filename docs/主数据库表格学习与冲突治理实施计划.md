# 主数据库表格学习与冲突治理实施计划

## 一、目标与边界

本功能把管理员持续提供的 Excel 表格转化为可审计、可复核、可回滚的主数据增量。上传文件不得直接修改正式主数据库，必须经过“上传分析、冲突治理、人工确认、合并发布”四个阶段。

本期学习以下稳定关系：

- 供应商名称 → 供应商编码。
- 材料编号 → 材料名称。
- 材料编号 → 规格。
- 材料编号 → 单位。
- 材料编号 → 供应商。

字段识别由集中注册表维护，新增业务模块或新表头时只扩展关系定义和字段别名，不在服务端或前端散落判断。管理员账号体系属于 Web 服务端，因此本期在 Web 管理中心提供治理界面；Core 保持无界面依赖，后续如需在 Tauri 中提供本地导入，可直接复用同一核心能力。

## 二、完整工作流

```text
管理员上传 Excel
  → 校验类型、大小与文件指纹
  → 按工作表识别表头和关系字段
  → 生成带来源行号的候选关系
  → 与同一文件及正式主数据库比较
  → 无冲突：等待管理员确认
  → 有冲突：管理员在系统内逐项决定
  → 全部冲突已处理：等待管理员确认
  → 确认后进入待合并队列
  → 管理员立即合并或维护循环定期合并
  → 合并前重新检查正式主数据库
  → 备份、锁内读改写、原子替换
  → 标记已合并并保留来源与决策记录
```

## 三、数据模型

每个导入批次保存独立 JSON 元数据和用户隔离的原始 Excel 文件。批次至少记录：

- 批次 ID、文件名、SHA-256、大小、上传管理员、创建时间。
- 状态：`needs_review`、`ready_to_confirm`、`ready`、`merged`、`rejected`、`failed`。
- 已识别工作表、未识别工作表及说明。
- 候选关系类型、规范化键、候选值、正式库当前值。
- 来源文件、工作表、Excel 行号。
- 冲突原因、管理员决策、最终值、决策人和决策时间。
- 确认人、确认时间、合并时间和合并摘要。

原始文件存放在 `web-data/users/<管理员ID>/master-data-imports/<批次ID>/`；导入索引和批次元数据存放在 `web-data/master-data-imports/`，只允许管理员接口访问。页面和 API 不返回服务端绝对路径。

## 四、冲突定义与决策

以下情况均视为冲突：

- 同一上传文件中，同一关系键出现多个不同非空值。
- 上传候选值与正式主数据库当前值不同。
- 批次确认后、实际合并前，正式库被其他任务更新为不同值。

管理员可选择：

- 保留正式库当前值。
- 使用上传表中的指定候选值。
- 手动填写规范值。
- 忽略这条关系，不纳入主数据库。

所有冲突处理都保留来源、决策人和时间。未处理冲突的批次不能确认；未确认批次不能合并；自动合并不得覆盖新出现的冲突。

## 五、幂等、并发与恢复

- 文件指纹相同且已有未拒绝批次时，拒绝重复上传并返回原批次提示。
- 合并以批次 ID 和候选关系为幂等边界，已合并批次重复执行不产生新写入。
- `material_catalog` 的读取、修改和写入必须处于同一个 `storage_lock.file_lock` 事务内，消除并发丢失更新。
- 每次实际修改正式主数据库前，在导入批次目录保存带时间戳的主数据快照。
- 正式主数据库和导入 JSON 均使用同目录临时文件与 `os.replace()` 原子替换。
- 合并阶段重新读取正式主数据库并复核冲突；若发现新冲突，批次退回 `needs_review`，不写正式库。

## 六、定期合并策略

- 服务端维护循环定期调用主数据合并检查。
- 仅处理管理员已确认的 `ready` 批次。
- 同一次维护最多按创建时间顺序处理有限数量批次，避免长期占用服务线程。
- 同时保留“立即合并”按钮，便于管理员完成复核后即时发布。
- 自动合并结果写入现有管理操作记录；失败只记录批次错误，不影响其他批次与正式主库。

## 八、分阶段验收门槛

### 阶段 A：安全存储和分析核心

- 上传表格不会直接改变正式主数据库。
- 能识别至少五类关系，并记录工作表与行号。
- 未识别字段时给出明确说明，不猜测、不静默写入。
- 同文件重复上传不会生成重复批次。
- 主数据库并发读改写不存在丢失更新窗口。

### 阶段 B：冲突治理与发布

- 文件内冲突和正式库冲突均可复现、可追溯。
- 所有冲突可在 API 层完成保留、采用、手填或忽略。
- 未处理冲突不能确认；未确认批次不能合并。
- 合并前发生的新冲突会安全退回复核。
- 合并失败不损坏正式主数据库，并保留合并前快照。

### 阶段 C：管理员 Web 体验

- 普通账号无法上传、查看批次、处理冲突或合并。
- 管理员可在主数据页完成上传到发布的完整流程。
- 页面显示业务名称、状态、来源和可操作建议，不展示 JSON、绝对路径或堆栈。
- 360px 移动端无横向页面溢出；表格区域允许局部滚动。
- 键盘可达、焦点可见、减少动画设置有效。

### 阶段 D：定期合并与回归

- 维护循环只合并 `ready` 批次，重复执行保持幂等。
- 自动合并有数量上限，单批失败不阻塞其他批次。
- Core 定向测试、Web 服务端测试、Python 全量回归、Web/Tauri 构建和 Rust 测试通过。
- `docs/项目全景-模块与实现.md` 与最终实现一致。

## 九、不在本期恢复或引入的内容

- 不恢复旧 Qt 业务入口或旧打包链路。
- 不让前端直接解析或修改 Excel。
- 不把管理员上传文件放入普通数据库文件列表。
- 不允许自动学习覆盖未处理冲突。
- 不在 Tauri 中复制 Web 管理员账号体系。
