# 峰运通数据管理系统前端视觉统一与工作台美化实施计划

> 制定日期：2026-08-03  
> 适用范围：`web-app/`、`tauri-app/`，以及工作台展示口径所必需的少量 `web_server.py` API 调整  
> 目标读者：后续负责实现的代码模型或开发人员  
> 本文只描述目标实现，不记录过渡态；实施时仍须遵守仓库根目录 `AGENTS.md`。

## 一、最终目标

把当前工作台已经形成的“业务调度台”思路提炼成全项目统一的设计系统，并同步覆盖 Web 与 Tauri 桌面端。

最终界面应呈现为：

- 深海军蓝应用外壳，稳定、专业、可信；
- 冷白或中性浅灰工作区，信息密度高但不拥挤；
- 品牌蓝用于主要操作，蓝青渐变只用于品牌和极少数强调位置；
- 绿、黄、红只表达状态，不作为装饰色；
- 低阴影、清晰边框、克制圆角，减少玻璃、发光和漂浮感；
- 工作台优先回答“现在要处理什么”，而不是展示等权重指标卡片；
- Web 与 Tauri 共享品牌、令牌、组件语义、状态和动效规范，但保留各自工作流差异；
- 移动端不是桌面布局的缩小版，而是按移动任务重新排序和组织。

建议将该视觉方向命名为：**冷静的工业运营台**。

## 二、实施边界

### 2.1 必须保持不变

- `core/` 继续作为业务唯一事实源，不把业务算法复制到前端。
- Web 继续只调用同源 `/api`，Tauri 继续通过白名单调用 `core.tauri_bridge`。
- 上传、预检、人工复核、执行、取消、下载、预览等现有协议不得退化。
- Web 用户数据隔离、权限判断、管理员能力、登录安全不得因改版放宽。
- Tauri 原生文件选择、拖放、sidecar、结果目录打开、远程 Web 模式不得退化。
- 默认管理员账号和密码不得出现在登录页或任何客户界面。

### 2.2 本轮不建议做的事

- 不引入大型 UI 框架或重量级图表库。
- 不为统一样式而把 Web 与 Tauri 强行合并成同一套 React 运行时代码。
- 不改变业务字段、输出格式和人工复核协议，除非现有展示口径确实误导用户。
- 不继续向现有大 CSS 文件末尾追加覆盖补丁。
- 不用更多渐变、阴影和动画掩盖信息层级问题。

## 三、现状诊断

### 3.1 Web 实际工作台入口

当前真正渲染的是：

- `web-app/src/App.tsx` 中的 `DispatchBoard`；
- `web-app/src/DispatchBoard.tsx`；
- `web-app/src/dispatch.css`。

`web-app/src/DashboardPage.tsx` 当前没有被引用，`App.tsx` 内的 `Metric` 和 `OverviewPage` 也是旧工作台遗留。后续实现必须以 `DispatchBoard` 为基线，不能误改旧页面后宣称完成。

### 3.2 风格不统一的根因

当前 Web 同时存在三种视觉语言：

1. 侧栏：深蓝渐变、蓝青选中态、发光强调；
2. 顶栏与普通页面：浅色玻璃、蓝色阴影、大圆角 SaaS 卡片；
3. 工作台：独立的深灰仪表带、中性纸面、紧凑几何和 `--dsp-* / --sig-*` 令牌。

工作台的信息架构值得保留，但它现在是一套孤立的局部设计系统。正确方向不是把工作台改回普通卡片墙，而是把工作台的克制、任务导向语言提炼成全局系统。

### 3.3 已知工程问题

- `web-app/src/styles.css` 约 1043 行、130KB，暗色和移动端大量依赖追加式覆盖。
- `web-app/src/dispatch.css` 约 802 行，仅一个页面就维护第二套颜色、圆角和主题。
- `tauri-app/src/styles.css` 约 625 行，后半段又追加“流光工作台”覆盖层，同一选择器多次定义。
- Web 普通页面与工作台的 1180px 内容宽度计算方式不同，页面切换时左右边界会跳动。
- `dispatch.css` 使用未定义的 `--dsp-r-lg`，卡片圆角声明会失效。
- Tauri 对账单扫描区域误用了 Web 变量 `--paper / --muted / --ink`，Tauri 根令牌并未定义这些变量。
- Web 多个页面借用来源型类名，例如报表页借用 `admin-card`，安全页借用 `auth-notice`，说明缺少真正的通用 UI 原语。
- Web 大量核心文字只有 9～11px，桌面办公屏和移动端都显得细碎、不够精致。
- Web 移动端把全部导航塞入横向滚动底栏，管理员入口过多，发现性差。
- `GuidedTour` 使用 `nth-child` 定位导航，导航顺序变化后说明已经错位。

### 3.4 工作台展示口径风险

视觉重排前必须先确认以下语义：

- 当前“排队 → 处理中 → 待复核 → 已完成”混合了当前状态与历史累计完成量，不应继续用箭头表现为同一批任务的流水线。
- 当前“近七日吞吐”实际更接近“按创建日期统计的任务创建量”，标题有误导风险。
- 当前“今日已完成”实际是“今天创建的任务中目前已完成多少”，不是“今天总共完成多少”。
- 状态总数、趋势、功能排行的查询范围并不完全一致，页面没有说明统计口径。

推荐优先采用前端可落地的安全方案：取消误导性箭头，改为“当前任务状态”块；将趋势改名为“近七日任务创建量”；将今日摘要写成“今日创建 / 其中已完成”。如果业务确实需要“按完成日期统计”，再由服务端补充完成时间和一致的 SQL 聚合。

## 四、统一设计原则

1. **行动优先**：先显示需要用户处理的事项，再显示状态、历史和趋势。
2. **信息先于装饰**：图表、颜色和动画都必须承载信息。
3. **一种表面语言**：应用外壳、工作台、表单、表格和弹窗共用同一组表面、边框与圆角令牌。
4. **状态语义稳定**：同一状态在 Web、Tauri、工作台、任务中心和人工复核中使用同一文字、颜色和图形。
5. **移动端独立编排**：移动端按任务优先级重排，不依赖桌面 CSS 缩列。
6. **客户化表达**：不向普通用户显示 job_id、内部动作名、堆栈、路径、bridge、Python 或调试术语。
7. **渐进迁移**：每迁移一个页面就删除对应旧规则，不在最后一次性清理。
8. **双端同语不同形**：Web 面向账号、团队协作与移动端；Tauri 面向本机批处理、原生文件能力和桌面多任务。

## 五、视觉系统规格

### 5.1 颜色令牌

建立语义令牌，不再在组件 CSS 中直接使用 `blue/cyan/purple` 等视觉命名。

| 语义 | 浅色建议值 | 深色建议值 | 用途 |
|---|---:|---:|---|
| `--fyt-canvas` | `#F4F7FB` | `#0B1322` | 页面画布 |
| `--fyt-surface` | `#FFFFFF` | `#131E30` | 普通卡片、表格、表单 |
| `--fyt-surface-subtle` | `#F7F9FC` | `#192538` | 次级区域、表头、筛选条 |
| `--fyt-surface-inverse` | `#0F1C33` | `#091120` | 侧栏、深色状态带 |
| `--fyt-surface-inverse-raised` | `#16294A` | `#13213A` | 深色悬浮和选中表面 |
| `--fyt-text` | `#17233B` | `#E5ECF6` | 主文字 |
| `--fyt-text-secondary` | `#52647D` | `#B1BED0` | 正文说明 |
| `--fyt-text-muted` | `#65758B` | `#8E9DB1` | 辅助信息，仍须满足对比度 |
| `--fyt-border` | `#DDE5EF` | `#2A394D` | 普通边框 |
| `--fyt-border-strong` | `#C9D5E3` | `#3B4D64` | 强分隔、选中边框 |
| `--fyt-primary` | `#2F6BFF` | `#6BA2FF` | 主操作、选中态 |
| `--fyt-primary-strong` | `#2455E6` | `#8AB5FF` | 主操作 hover |
| `--fyt-accent` | `#21C8C6` | `#45D5D2` | 品牌辅助色、少量强调 |
| `--fyt-info` | `#2F7FE8` | `#62A5FF` | 处理中、信息 |
| `--fyt-success` | `#14875C` | `#3FC78D` | 完成、正常 |
| `--fyt-warning` | `#B5760C` | `#F0AE3C` | 排队、待确认、需注意 |
| `--fyt-danger` | `#CF3341` | `#FF6B76` | 失败、中断、危险操作 |
| `--fyt-neutral` | `#6C7D91` | `#8D9DB0` | 已取消、停用、未知 |

同时建立每个状态的浅底令牌，例如 `--fyt-success-soft`，避免组件自行混色。除令牌文件、插画和必要的数据可视化外，页面 CSS 不应再出现新的十六进制颜色字面量。

### 5.2 排版

- 中文正文：`Microsoft YaHei UI`、`Microsoft YaHei`、`PingFang SC`、`Segoe UI`。
- 拉丁和数字可继续使用自托管 Plex；数字、金额、批次号、日期、进度采用等宽数字。
- 页面主标题：24px / 700；移动端 20px。
- 区块标题：18px / 700。
- 卡片标题：14px / 650。
- 正文：14px / 1.7。
- 辅助文字：12px / 1.6。
- 仅徽标、极短标签可使用 11px；禁止用 9～10px 承载核心信息。
- 中文标题不使用负字距或大幅字间距；英文缩写可例外。

### 5.3 间距、圆角与阴影

- 基础间距步进：4、8、12、16、20、24、32、40、48。
- 控件高度：小型 32px，常规 40px，主要操作 44px；移动触控目标不小于 44×44px。
- 控件圆角：8px。
- 卡片圆角：12px。
- 大型容器和弹窗圆角：16px。
- 胶囊、徽标：999px。
- 普通表面以边框分层，默认无阴影或只用极轻阴影。
- 仅弹窗、抽屉、悬浮工具条使用提升阴影。
- 不再使用整卡持续发光、大片环境光和高频玻璃模糊。

### 5.4 布局令牌

- Web 桌面侧栏：232px；平板图标栏：72px。
- Tauri 桌面侧栏：224px；收起后 64px。
- Web 顶栏：68px；移动端命令栏：56px。
- Tauri 顶栏：72px。
- 主内容最大宽度：1240px。
- 页面 gutter：桌面 32px，平板 24px，移动端 16px。
- 卡片间距：桌面 20px，移动端 12px。
- Tauri 右侧快捷面板：300px；小于 1180px 时改为覆盖式抽屉，不压缩主内容。

所有 Web 页面必须使用同一个 `ContentContainer`。最大宽度与左右 gutter 分开计算，禁止工作台另建一套宽度变量。

### 5.5 动效

建立统一动效令牌：

- `--motion-fast: 120ms`
- `--motion-base: 180ms`
- `--motion-slow: 260ms`
- 标准缓动：`cubic-bezier(.2,.75,.25,1)`

允许：

- 页面切换时 4～8px 的轻微位移和淡入；
- 抽屉、弹窗、折叠区域的进入退出；
- 进度、选中态和错误反馈；
- 新增列表项的短暂出现动画。

禁止：

- 无状态变化时持续漂浮、流光、旋转、发光；
- 所有卡片统一上浮；
- 刷新数据时重播整页入场动画；
- 使用 `transition: all`；
- 仅为“显得高级”而添加背景动画。

`prefers-reduced-motion` 和 Tauri 的“减少动画”设置必须关闭位移、缩放、循环和视图过渡，只保留必要的颜色/透明度反馈。

## 七、Web 工作台完整蓝图

### 7.1 信息阅读顺序

工作台必须按以下顺序回答用户问题：

1. 现在有没有需要我处理的事；
2. 当前有哪些任务正在排队、处理、待确认或异常；
3. 我现在可以从哪里继续工作；
4. 最近有哪些任务和输出；
5. 最近七天的任务变化如何。

### 7.2 桌面布局

使用 12 列网格：

```text
┌─────────────────────────────────────────────────────────────┐
│ 页面标题 / 更新时间 / 刷新 / 主要操作                       │
├─────────────────────────────────────────────────────────────┤
│ 当前任务状态：待确认｜处理中｜排队｜异常｜今日创建/已完成   │
├───────────────────────────────────┬─────────────────────────┤
│ 最近任务与对应输出（8 列）        │ 需要处理（4 列）        │
│ 默认 5～6 条，可打开任务详情      ├─────────────────────────┤
│ 文件作为任务的二级内容            │ 快速开始                │
│                                   ├─────────────────────────┤
│                                   │ 近七日任务创建量        │
└───────────────────────────────────┴─────────────────────────┘
```

具体要求：

- 深色状态带继续保留，但颜色、圆角、边框必须引用全局令牌，并与侧栏深海军蓝同源。
- 状态区改为可点击状态块，不再用误导性流水线箭头。
- “已完成”从当前状态中移出，作为今日或历史摘要。
- 右栏第一块必须是“需要处理”，不能被趋势和快捷入口压到后面。
- “脱轨”改为客户化文案“异常任务”或“失败或中断”。
- 状态块点击后进入任务中心对应筛选；现有 `active/review/completed/failed` 筛选应直接复用。
- 最近任务整行可打开，文件下载按钮是二级操作，二者事件不得冲突。
- 默认只显示 5～6 个最近任务，避免右栏待办被长列表推到底部。
- 通知只展示最多 3 条重要内容，并提供“查看全部消息”。

### 7.3 趋势图

- 仍使用轻量 CSS 或 SVG，不增加大型图表依赖。
- 若后端不改，标题使用“近七日任务创建量”，并显示“按任务创建日期统计”。
- 柱顶直接显示总量；失败数必须有文字或图形说明，不能只放在 hover `title`。
- 显示七日合计、失败总量、日均值和“截至当前”。
- 提供屏幕阅读器文本摘要或隐藏数据表。
- 工作台只展示短期操作趋势，长期分析仍放在报表中心。

### 7.4 新账号和空态

- 即使 `feature_usage` 为空，也必须显示“快速开始”。
- 推荐顺序：用户收藏 → 最近使用 → 角色推荐 → 默认推荐模块。
- 无任务时提供明确下一步，不出现“从右侧快速开始”但右侧为空的矛盾文案。
- 无待办时显示紧凑成功状态：“当前没有待处理事项，可以开始新的业务处理”。

### 7.5 加载、刷新和失败

- 初次加载使用结构化骨架，不只显示“正在加载工作台”。
- 手动刷新时保留旧数据，按钮进入 loading 状态，刷新完成后更新“已更新于”。
- 绿色“实时”圆点只能在确实存在自动刷新时使用；否则改成普通更新时间。
- 工作台主体、通知角标和概览请求应建立独立错误边界，单个接口失败不能清空整个页面。
- 可考虑 `Promise.allSettled`，或统一 `/api/dashboard` 返回未读数，避免重复请求。
- 普通用户只看到客户化错误摘要；技术详情只在受控管理员入口中显示。

## 十三、可访问性与客户化文案

### 13.1 可访问性

- 正文与背景至少达到 WCAG AA 4.5:1。
- 状态不得只靠颜色，必须有文字和必要的图标/形状。
- 所有图标按钮必须有 `aria-label` 和可见焦点环。
- 状态块、任务行、导航、标签页、抽屉和弹窗支持键盘操作。
- `time` 元素提供 `dateTime`。
- 刷新、上传、运行、取消、成功和失败使用 `aria-live` 或 `aria-busy`。
- 图表提供直接数值、文本摘要和屏幕阅读器数据。
- 表格应有标题/列头；窄屏采用横向滚动、摘要行或详情抽屉，不能把所有字段硬挤成卡片。
- 移动触控目标不小于 44×44px。

### 13.2 文案规范

优先使用业务语言：

- “异常任务”，不用“脱轨”；
- “处理中”，不用“running”；
- “重新处理”，不用“重跑 sidecar”；
- “已更新于 10:29”，不用未实现实时刷新时的“实时”；
- “部分数据暂时无法读取”，不用“Promise 请求失败”；
- “查看详细原因”与受控技术详情分开。

客户界面不得直接展示内部路径、动作键、异常堆栈和调试日志。

- 工作台刷新、状态跳转、复核入口、下载和消息入口；
- 文件上传、拖放、预检、取消和结果下载；
- 所有人工复核类型；
- 移动车间问题发布、图片预览和导出；
- 数据库权限、编辑、删除、恢复和版本；
- 消息、公告、账号审核和管理员授权；
- Tauri 文件选择、拖放、任务取消、打开输出目录；
- Tauri 本地/服务器模式和快捷面板。

### 17.4 视觉验收

- 任意页面切换时内容左边缘和最大宽度不跳动。
- 工作台、侧栏、顶栏和普通页面明显属于同一产品。
- 亮色与暗色都没有写死浅色表面或过曝状态底色。
- 常规正文不低于 12px，主要正文达到 14px。
- 卡片圆角、控件高度、按钮层级和状态色一致。
- 不存在无业务意义的持续动画。
- 360px Web 页面无非预期横向滚动。
- Tauri 900px 窗口仍可完成主要业务。

## 十八、禁止事项

后续实现模型不得：

- 继续单独雕刻 `dispatch.css` 而不建立全局设计系统；
- 只改工作台、不迁移侧栏、顶栏和高频业务组件；
- 在旧 `styles.css` 末尾继续追加“最终修复”覆盖层；
- 新增一套第三方组件库后与现有样式混用；
- 用颜色作为唯一状态信号；
- 在移动端保留无限横向滚动导航；
- 把桌面表格简单变成字段挤压的卡片墙；
- 显示内部错误、路径、动作键、堆栈或默认管理员凭据；
- 为视觉统一破坏 Tauri 原生能力或 Web 权限逻辑；
- 未跑构建和关键回归就删除旧入口或样式。
