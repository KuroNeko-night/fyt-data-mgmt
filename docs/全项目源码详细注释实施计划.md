# 全项目源码详细注释实施计划

## 一、目标

在不改变接口、业务结果、数据库结构、权限规则和部署方式的前提下，为项目维护的源码补充系统化中文注释。注释重点解释设计原因、数据边界、状态变化、异常处理、并发与事务、路径安全、历史兼容和业务规则，避免只把代码翻译成自然语言。

本次工作同时解决以下维护问题：

- 阅读函数时只能知道“做什么”，无法快速判断“为什么这样做”；
- 复杂分支、特殊列识别、旧模板兼容和回退逻辑缺少上下文；
- Web 服务端的权限、文件隔离、事务和后台任务边界不够直观；
- React 状态流转、异步请求、响应式布局与动画缺少维护说明；
- Windows/Linux 部署脚本中的权限、回滚和服务管理步骤容易被误删；
- 测试用例没有说明它所保护的历史缺陷和关键不变量。

## 三、注释质量标准

### 3.1 模块级说明

每个承担实际逻辑的模块需要说明：

- 模块负责什么；
- 它不负责什么；
- 上游输入和下游输出；
- 重要的线程、进程、文件或数据库边界。

纯导出文件、类型聚合文件和空包初始化文件只需说明存在原因，不重复描述每个导出项。

### 3.2 函数和方法说明

函数说明不得只写“处理数据”“返回结果”。复杂函数至少覆盖其中适用的内容：

- 输入格式、可选值和默认行为；
- 返回字典中关键字段的语义；
- 是否修改文件、数据库、缓存或进程状态；
- 可能抛出的异常以及由哪一层转换；
- 并发、事务、幂等性和重试特性；
- 与旧模板、旧数据库或旧部署结构的兼容原因。

### 3.3 行尾与代码块注释

关键语句优先在同一行后写中文注释，重点包括：

- 容易误删的边界判断；
- 不明显的单位换算、索引偏移和日期范围；
- Excel 行列坐标、合并单元格、公式缓存和模板复制；
- SQL 更新条件、事务顺序和锁的原因；
- 路径 `resolve()`、父目录检查和账号隔离；
- 后台线程、子进程、标准流协议和取消行为；
- React 中避免竞态、重复请求或陈旧状态的写法；
- CSS 中为动画性能、层叠上下文或移动端适配设置的特殊属性。

当行尾注释会导致代码过长、破坏 JSX/TSX 语法或降低表格型代码可读性时，改为紧邻代码块之前的详细注释。不得为了满足“同一行”而生成无效 JSX、Shell 或多行字符串。

### 3.4 禁止的注释

- 不写“给变量赋值”“进入循环”“返回结果”一类复述语句；
- 不解释 Python、React、Rust 的基础语法；
- 不保留迁移过程、调试临时结论或模型思考文本；
- 不把当前实现描述成未来计划；
- 不写与代码行为不一致、无法由测试或实现验证的推测；
- 不使用英文占位、乱码、问号或无法在 GBK 控制台显示的装饰符号。
