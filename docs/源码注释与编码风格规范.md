# 源码注释与编码风格规范

本文是峰运通数据管理系统的**长期编码约束**，不是实施计划。它规定维护源码中的注释质量、
代码组织边界和可读性底线。新增模块、重构和复杂改动都必须满足本文；阶段性计划、完成状态
和验收记录不属于本文内容。

仓库级目录、依赖、打包和安全约束以根目录 `AGENTS.md` 为最高优先级；本文只负责“注释
怎么写、代码怎么保持可读”，不与 `AGENTS.md` 冲突。

## 一、适用范围

### 1.1 维护源码

以下内容属于项目维护源码，必须遵守本文：

- `core/`、`web_backend/`、`web_server.py`、`web_control_gui.py`；
- `web-app/src/`、`tauri-app/src/`、`tauri-app/src-tauri/src/`；
- `scripts/` 下的 Python、PowerShell、JavaScript/MJS 脚本；
- `packaging/` 下的 Linux Shell、PyInstaller spec 和部署模板；
- `tests/` 下的测试模块；
- 手写 CSS 和设计令牌源文件（生成文件不手工修改）。

### 1.2 非维护内容

以下内容不要求注释，也不得为了追求覆盖率而修改：

- `.venv/`、`node_modules/`、Rust `target/` 等依赖与编译缓存；
- `dist/`、`build/`、`gen/`、`binaries/` 等生成产物；
- `web-data/`、`docker-data/`、日志、缓存、上传文件和真实业务数据；
- `package-lock.json`、`Cargo.lock` 等机器维护的锁文件；
- 图片、字体、压缩包、数据库和二进制文件；
- JSON 数据文件不支持标准注释，不得写入非法字段。

## 二、注释总则

1. **解释原因和边界，不复述语法**。注释回答“为什么这样写、什么情况下会被打破、失败
   后如何恢复”，不写“给变量赋值”“进入循环”“返回结果”。
2. **中文注释，UTF-8 编码**。禁止乱码、`U+FFFD` 替换字符、连续问号和无法在 GBK 控制台
   显示的装饰符号。
3. **注释必须与代码一致**。只描述当前实现；不写未来计划、迁移过程、调试临时结论或
   无法验证的推测。
4. **高风险逻辑必须有就近注释**：权限判断、路径校验、事务顺序、并发边界、失败回滚、
   历史兼容、Excel 坐标与公式缓存、SQL 更新条件、标准流协议、子进程取消、React 请求
   竞态和陈旧状态。
5. **简单代码保持简洁**。一行断言、直接返回、简单赋值等不添加赘余注释。

## 三、模块级注释

每个承担实际逻辑的模块必须有模块 docstring/文件头注释，说明：

- 模块负责什么；
- 模块不负责什么；
- 上游输入和下游输出；
- 线程、进程、文件、数据库或网络边界；
- 与其他模块的拆分关系（如 `pivot_core` 与 `pivot_analysis`、`pivot_clustering` 的分工）。

纯导出文件、类型聚合文件和空包初始化文件只需说明存在原因，不重复描述每个导出项。

## 四、函数与方法注释

函数 docstring 不得只写“处理数据”“返回结果”。复杂函数至少覆盖适用项：

- 输入格式、可选值和默认行为；
- 返回结构中关键字段的语义；
- 是否修改文件、数据库、缓存或进程状态；
- 可能抛出的异常以及由哪一层转换；
- 并发、事务、幂等性和重试特性；
- 与旧模板、旧数据库或旧部署结构的兼容原因。

内部辅助函数同样要有简短 docstring；嵌套函数允许只说明其闭包目的，但不得为空。

## 五、行内与代码块注释

关键语句优先就近写中文注释：

- 容易误删的边界判断；
- 不明显的单位换算、索引偏移和日期范围；
- Excel 行列坐标、合并单元格、公式缓存和模板复制；
- SQL 更新条件、事务顺序和锁的原因；
- 路径 `resolve()`、父目录检查和账号隔离；
- 后台线程、子进程、标准流协议和取消行为；
- React 中避免竞态、重复请求或陈旧状态的写法；
- CSS 中为动画性能、层叠上下文或移动端适配设置的特殊属性。

当行尾注释会导致代码过长、破坏 JSX/TSX 语法或降低表格型代码可读性时，改为紧邻代码块
之前的详细注释。不得为了满足“同一行”而生成无效 JSX、Shell 或多行字符串。

## 六、禁止的注释

- 不写“给变量赋值”“进入循环”“返回结果”一类复述语句；
- 不解释 Python、React、Rust 的基础语法；
- 不保留迁移过程、调试临时结论或模型思考文本；
- 不把当前实现描述成未来计划；
- 不写与代码行为不一致、无法由测试或实现验证的推测；
- 不使用英文占位、乱码、问号或装饰符号；
- 不把内部动作 key、绝对路径、任务 ID 或调试口径写进客户可见文案。

## 七、分语言注释要求

### Python

- 模块、类、函数、方法必须有中文 docstring。
- 复杂函数补充 `Args:`/`Returns:`/`Raises:` 或自然语言契约；风格以现有 `core/`、
  `web_backend/` 为准，不强求 sphinx 标记。
- 注释重点：业务不变量、事务顺序、并发边界、路径安全、失败回滚、兼容原因。
- `tauri_bridge.py`、`web_backend` 入口的参数校验和动作白名单必须说明为什么每个字段
  需要校验。

### TypeScript / TSX

- 文件头说明职责；组件、hook、类型/接口补充 JSDoc。
- 注释重点：数据流、状态派生、请求竞态、权限矩阵、组件边界、焦点管理、滚动容器和
  `prefers-reduced-motion`。
- 不在 JSX 中间插入行尾注释；需要说明时写在 JSX 块之前。

### Rust

- 只注释 `src-tauri` 下的维护源码。
- 注释重点：命令白名单、路径校验、sidecar 定位、无窗口子进程、标准流协议、进程表
  登记与取消。

### PowerShell / Shell / PyInstaller spec

- 说明每个启动、停止、安装和升级步骤的边界；危险操作（删除、覆盖、提权、停止进程）
  必须写清前提和回滚。
- 注释重点：数据保护、PID 文件、临时目录、原子替换、权限属主、ASCII 正式路径。
- 脚本开头说明调用方式；参数含义与默认值。

### 测试

- 注释重点不是逐行解释断言，而是说明：
  - 用例对应哪个历史缺陷或业务不变量；
  - 合成表格为什么采用特定布局；
  - 哪些断言保护权限、隔离、回滚或模板兼容；
  - mock/patch 替代了什么外部条件；
  - 等待循环与超时为何使用当前数值。
- 简单的一行断言不添加赘余注释；复杂 fixture、辅助构造器和多阶段 API 流程必须说明。

## 八、代码组织与复杂度约束

为保持可读性，新增和重构代码遵守以下边界：

1. **文件规模**：Python/TS/TSX 源文件超过 800 行应优先按职责拆分；无法拆分时在模块
   docstring 中说明原因。`web_server.py`、`web_control_gui.py`、`tauri_bridge.py` 等
   兼容入口除外，但仍需按节注释。
2. **函数规模**：单个函数超过 80 行或圈复杂度超过 15 时，应拆分为语义清晰的辅助函数；
   确需保留的长函数必须用 docstring 说明阶段划分。
3. **嵌套深度**：业务代码嵌套深度不超过 4 层；超过时必须提取辅助函数或早退重构。
   XML 生成、格式转换等难以避免深嵌套的底层代码可以在文件头说明原因。
4. **命名**：Python 使用 `snake_case`，React 组件使用 `PascalCase`，Rust 遵循 rustfmt；
   内部函数与公开入口的命名要能区分“兼容门面”和“实现模块”。
5. **导入**：Python 标准库、第三方、项目内导入分段排列；项目内优先使用相对导入
   （`core/`、`web_backend/` 内），入口文件可按现有方式导入。
6. **错误处理**：业务核心异常向上抛出，不静默吞掉；`log`/`progress` 只报告状态。
   兼容门面只转发公开入口，不复制业务实现。
7. **并发与事务**：涉及 SQLite 写操作、JSON 索引读改写、文件加锁的代码必须注释锁顺序
   和回滚路径。
8. **路径安全**：所有来自用户或前端的路径参数，必须在进入文件系统前注释说明校验点
   （归属、目录穿越、绝对路径）。

## 九、验证命令

提交前在仓库根目录执行：

```powershell
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe scripts\check_repository_hygiene.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
npm --prefix web-app run build
npm --prefix tauri-app run build
Set-Location tauri-app\src-tauri
cargo test
```

Linux Shell 脚本使用 Git Bash 执行 `bash -n`；PowerShell 脚本使用 Windows PowerShell
AST 解析；发布与补丁构建只在临时目录进行内容验证，不读取、复制或覆盖生产 `web-data`。

## 十、评审检查清单

新增模块或复杂改动合并前逐项确认：

- [ ] 模块 docstring 说明职责、边界和上下游；
- [ ] 复杂函数 docstring 说明输入、返回、副作用、异常、并发/事务/兼容原因；
- [ ] 高风险分支和难懂代码块有就近中文注释；
- [ ] 没有复述语法、迁移过程、未来计划或无法验证的推测；
- [ ] 没有 `U+FFFD`、连续问号和 GBK 控制台不可显示字符；
- [ ] 文件规模、函数复杂度和嵌套深度满足本文第八章；
- [ ] 相关 Python 回归、双端构建和 Rust 测试通过；
- [ ] 行为、接口、权限、输出格式或部署方式变化已同步 `docs/项目全景-模块与实现.md`。
